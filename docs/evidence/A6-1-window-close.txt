WHAT THE WINDOW HANDLE SHOWS
  The window really did close: the title went empty and the original handle was
  replaced. The PROCESS did not exit. That one line is the diagnosis -- a
  process that outlives its window means the Tauri event loop never ended, so
  RunEvent::Exit never fires, so the exit hook at
  apps/pos/src-tauri/src/lib.rs:199-243 -- which is correct and complete -- is
  never reached. The bug is not in the hook; it is that nothing calls it.

WHAT THIS DOES AND DOES NOT MEAN
  No data is lost. recover_crash_leftovers (edge/database/src/crypto.rs:312)
  proves the key, folds any WAL pages in and reseals the leftover on the next
  open; an unreadable leftover is quarantined with its bytes intact.
  The real harm is narrower:
    1. A decrypted SQLite file holding cached Argon2id credential hashes sits
       on disk in the clear between an abnormal exit and the next open
       (ADR-011).
    2. A backup that copies only edge.db.enc silently loses the last session,
       because the newer state is in the plaintext beside it. This run shows
       that gap directly: the sealed file was 17 minutes older than the
       plaintext at the moment of the close.
